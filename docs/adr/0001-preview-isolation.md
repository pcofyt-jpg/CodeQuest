# ADR 0001. Изоляция предпросмотра кода

Статус: принято для этапов 1–2. Пересмотреть до публичного запуска.

## Контекст

Ребёнок пишет произвольный HTML, CSS и JavaScript, и мы его выполняем. Код может быть ошибочным
(бесконечный цикл) или, если его кто-то подсказал, намеренно вредным: попытка прочитать данные
приложения, отправить их в сеть, открыть чужой сайт.

## Решение

Код выполняется только в `<iframe sandbox="allow-scripts" srcdoc="…">`. Защита многослойная:

| Слой | Что защищает | Где |
|---|---|---|
| `sandbox` без `allow-same-origin` | Непрозрачный origin: нет доступа к DOM, cookies, localStorage приложения; нельзя открыть окно, отправить форму, управлять вкладкой | `PreviewFrame.tsx` |
| CSP внутри документа | `default-src 'none'`, `connect-src 'none'`: нет сети и внешних ресурсов (картинок, шрифтов, скриптов) | `buildDocument.ts` |
| CSP приложения `frame-src 'none'` | Фрейм не может загрузить чужой сайт (srcdoc при этом работает) | `next.config.ts` |
| Обнаружение ухода | Если вместо страницы ребёнка загрузилось что-то другое, она открывается заново; при постоянных попытках предпросмотр останавливается | `PreviewFrame.tsx` |
| Защита циклов | Код разбирается парсером acorn, в каждый цикл вставляется проверка времени (1 с) | `loopProtect.ts` |
| Проверки — данные | Проверки задания передаются в песочницу как JSON, а не как код | `types.ts` |

Сообщения из фрейма принимаются, только если `event.source` — наш фрейм и токен совпадает
с текущей версией кода.

## Что проверено в Chromium 141

- Код во фрейме не может прочитать DOM приложения, localStorage и cookies, открыть окно, увести вкладку,
  сделать `fetch` и загрузить внешнюю картинку. Для картинки подтверждено, что запрос не уходит в сеть
  (блокировка CSP).
- Переход фрейма на внешний адрес блокируется `frame-src 'none'`.
- **Бесконечный цикл в srcdoc-фрейме замораживает всё приложение** (в эксперименте — на 2,8 с):
  фрейм того же сайта работает в том же процессе браузера. С защитой циклов студия замирает
  не дольше чем на ~1 с, затем ребёнок видит объяснение и ссылку на строку цикла.

Сквозные тесты: `e2e/t2_security.py`.

## Известные ограничения

1. **Один процесс.** Защита циклов обходится намеренно (например, долгая рекурсия без циклов
   или переопределение служебных функций). Это вредит только своему предпросмотру, но может
   подвесить вкладку. Полное решение — пункт 1 ниже.
2. **Наследование CSP.** srcdoc-документ наследует CSP приложения. Поэтому строгий `script-src`
   для основного приложения пока не включён: он сломал бы код ребёнка.
3. **Проверки в браузере.** Результат проверки можно подделать из кода ребёнка. Пока прогресс
   хранится только в браузере и ничего не даёт, это допустимо.
4. Другие браузеры (Safari, Firefox, мобильные) **не тестировались**. Это нужно сделать на этапе 7.

## Что сделать до публичного запуска

1. Вынести выполнение на **отдельный регистрируемый домен** (не поддомен основного), например
   `codequest-run.example`. Тогда браузеры с изоляцией сайтов запустят его в отдельном процессе,
   зависание не затронет приложение, а у основного приложения можно включить строгий CSP.
2. Страница-исполнитель на этом домене получает код через `postMessage` с проверкой origin
   и задаёт собственные строгие заголовки (CSP, `Cross-Origin-Opener-Policy` и др.).
3. Завершение урока засчитывает сервер: он повторяет проверки исходного кода, а DOM-проверки
   выполняет в изолированном headless-браузере или принимает частичное доверие осознанно.
4. Провести тесты безопасности со специалистом (см. `docs/RISKS.md`).
