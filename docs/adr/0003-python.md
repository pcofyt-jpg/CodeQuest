# ADR 0003. Python в браузере

Статус: принято (раздел «Python: первые шаги», 8 уроков).

## Решение

- **Движок — Pyodide 314.0.7** (настоящий CPython, скомпилированный в WebAssembly). Ошибки и поведение —
  как у Python, который дети встретят в школе (ОГЭ/ЕГЭ по информатике). Альтернативы (Skulpt, Brython)
  легче, но это не CPython: другие сообщения об ошибках и неполная совместимость.
- **Файлы Python отдаёт наш сайт** (`/pyodide/`, ~13,5 МБ без сжатия): `scripts/copy-pyodide.mjs` копирует их
  из `node_modules` перед сборкой. В git не хранятся. Загружаются один раз, дальше — из кэша браузера.
- **Программа выполняется в отдельном фоновом потоке (модульный Web Worker из blob:).**
  - Вечный цикл не вешает страницу; через 5 секунд поток уничтожается и создаётся заново.
  - Поток наследует политику страницы `connect-src 'self' <наставник>`: код ребёнка не может обращаться
    к другим сайтам. Проверено опытом: тот же код без политики достучался до стороннего сервера, со
    студийной политикой — нет (в обычном режиме и в режиме GitHub Pages, где политика только в `<meta>`).
  - У потока нет доступа к странице, cookies и localStorage.
- **Обвязка** (`src/lib/python/prelude.ts`) — одна для браузера и тестов: чистые переменные на каждый запуск,
  `input()` из поля «Ввод для программы» (по строке на вызов, ввод показывается в выводе), робот Кью на поле
  (стены, кристаллы, флажок, лимит 300 шагов), ошибка с типом и строкой в коде ребёнка.
- **Проверки** (`src/lib/python/checks.ts`): `pyRobot` (дошёл и собрал), `pyOutput` (при таком вводе вывод
  содержит фрагменты по порядку), `pyNoError`, плюс `source` по коду. Тесты запускают те же проверки
  в Pyodide под Node: эталон проходит, стартовый код — нет.

## Ограничения

- Наставник (YandexGPT) для уроков Python пока выключен: его правила и запрос рассчитаны на HTML/CSS/JS.
- Результат проверки вычисляется в браузере, как и у веб-уроков (см. ADR 0001).
- Первая загрузка на медленном мобильном интернете может занять 10+ секунд — студия показывает сообщение.
- Нужно проверить после выкладки, что GitHub Pages отдаёт `.wasm` с типом `application/wasm`.
