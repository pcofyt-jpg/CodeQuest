# Подготовка Yandex Cloud для ИИ-наставника

Решение и причины выбора — в `docs/adr/0002-ai-mentor.md`.
Здесь только подготовка, которую делает владелец аккаунта. Код функции появится на следующем шаге.

## Главное правило безопасности

**Не создавайте API-ключи и никому их не пересылайте — ни в чат, ни в код, ни в GitHub.**
Функция будет работать от имени сервисного аккаунта: Yandex Cloud сам выдаёт ей временный
токен при каждом вызове (`context.token.access_token`, см. документацию Cloud Functions,
«Контекст вызова функции на Node.js»). Постоянного секрета, который можно украсть, не будет.

## Шаги (названия кнопок могут немного отличаться — интерфейс консоли меняется)

1. **Платёжный аккаунт.** В консоли Yandex Cloud (console.yandex.cloud) откройте «Биллинг»
   и убедитесь, что платёжный аккаунт активен и привязан к облаку.
2. **Каталог.** В облаке создайте каталог `codequest`. В нём будет всё, что связано с наставником.
3. **Сервисный аккаунт.** В каталоге `codequest`: «Сервисные аккаунты» (Identity and Access Management)
   → «Создать» → имя `ai-mentor` → роль **`ai.languageModels.user`** (только она — она даёт право
   вызывать модели и больше ничего).
4. **Бюджет с оповещениями.** В «Биллинге» → «Бюджеты» создайте бюджет на облако, например 500 ₽ в месяц,
   с оповещениями на почту при 50 %, 90 % и 100 %. Для пилота на 10 семей ожидаемый расход — сотни рублей
   в месяц (оценка в ADR 0002), бюджет нужен на случай ошибки или злоупотребления.
5. **Идентификатор каталога.** Найдите ID каталога `codequest` (строка вида `b1g...`) и сохраните у себя —
   он понадобится в настройках функции. Это не секрет, но и публиковать его незачем.

## Что будет дальше (шаг 2)

- Код функции `ai-mentor` (Node.js) в репозитории, папка `functions/ai-mentor/`.
- Функция в каталоге `codequest` с сервисным аккаунтом `ai-mentor`, вызов модели с отключённым
  логированием запросов (`x-data-logging-enabled: false`).
- Код доступа для семей пилота и дневные лимиты.
- Тестовый набор ошибок из уроков для выбора между YandexGPT Lite и Pro.

# Шаг 2. Функция ИИ-наставника

Код функции — `functions/ai-mentor/` (файлы `index.js` и `package.json`, внешних библиотек нет).

## 1. Придумайте коды доступа (на своём компьютере, в папке проекта)

```powershell
node scripts/mentor-codes.mjs 3
```
Скрипт напечатает 3 кода для семей и одну длинную строку — хеши для настроек функции.
Коды раздавайте лично; в настройки функции вставляется только строка с хешами.
Чтобы отключить семью — уберите её хеш и сохраните новую версию функции.

## 2. Создайте функцию

1. Консоль Yandex Cloud → каталог `codequest` → **Cloud Functions** → «Создать функцию».
2. Имя: `ai-mentor` → «Создать».
3. Откроется редактор. Среда выполнения: **Node.js 22**. Способ: **редактор кода**.
4. Удалите пример и создайте два файла — `index.js` и `package.json` — с содержимым из
   `functions/ai-mentor/` (скопируйте целиком). **Код не меняйте** — ни ID каталога, ни коды
   в него не вписываются: все настройки задаются только в переменных окружения (пункт 5).
5. Параметры версии:
   - точка входа: `index.handler`;
   - таймаут: `30` секунд; память: `128 МБ`;
   - сервисный аккаунт: **`ai-mentor`** (без него функция не сможет обратиться к модели);
   - переменные окружения:

     | Имя | Значение |
     |---|---|
     | `FOLDER_ID` | ID каталога `codequest` (строка `b1g…`) |
     | `ACCESS_CODES_SHA256` | строка хешей из шага 1 |
     | `ALLOWED_ORIGINS` | `https://pcofyt-jpg.github.io,http://localhost:3000` |
     | `MODEL` | `yandexgpt` (Pro — выбран по сравнению, см. ADR 0002) |
     | `DAILY_LIMIT` | `30` |
     | `ALLOW_MODEL_CHOICE` | `1` — временно, для сравнения моделей; потом удалить |
6. «Сохранить изменения» — создастся версия функции.
7. На вкладке «Обзор» включите **«Публичная функция»** и скопируйте **ссылку для вызова**
   (вида `https://functions.yandexcloud.net/d4e…`). Публичная — значит её может вызвать браузер;
   без кода доступа она ничего не сделает.

## 3. Сравните модели (5 минут)

```powershell
$env:MENTOR_URL="ссылка_для_вызова"; $env:MENTOR_CODE="один_из_кодов"; node functions/ai-mentor/eval.mjs
```
Скрипт задаст обеим моделям 5 настоящих ошибок из уроков и напечатает ответы.
Пришлите вывод — код доступа в нём не печатается. После выбора модели удалите `ALLOW_MODEL_CHOICE`.
Проверить только выбранную модель: `$env:EVAL_MODELS="yandexgpt"` перед запуском.

## 4. Подключите наставника к сайту

GitHub → репозиторий → **Settings → Secrets and variables → Actions → вкладка Variables →
New repository variable**: имя `AI_MENTOR_URL`, значение — ссылка для вызова.
Затем Actions → «Выкладка на GitHub Pages» → Run workflow. Ссылка не секрет: браузер
всё равно обращается по ней, а защищает наставника код доступа.

На сайте: ошибка в консоли → «Спросить наставника» → родитель вводит код один раз.

## Если что-то не работает

Скрипт сравнения сам подсказывает, что исправить (строка «>>> Что исправить»). Коды причин:
`config_folder_id` — нет переменной FOLDER_ID; `config_codes_missing` — нет ACCESS_CODES_SHA256;
`config_codes_not_hashes` — в ACCESS_CODES_SHA256 вставлены коды вместо хешей;
`config_service_account` — не выбран сервисный аккаунт; `code` — код доступа не подходит.

- «Наставник ещё не настроен» — не указан `FOLDER_ID`, хеши или сервисный аккаунт.
- «Код доступа не подходит» — проверьте код и что его хеш есть в `ACCESS_CODES_SHA256`.
- «Наставник сейчас не отвечает» — откройте у функции вкладку «Логи»: там только служебные записи
  (`model_error` и код ответа), без кода детей. Частая причина — у сервисного аккаунта нет роли
  `ai.languageModels.user`.
