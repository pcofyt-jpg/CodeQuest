# Выкладка на GitHub Pages (закрытый пилот)

Сайт собирается в статические файлы и выкладывается автоматически при каждом изменении
ветки `main` (сценарий `.github/workflows/pages.yml`). Перед выкладкой запускаются проверки:
если тесты не прошли, сайт не обновится.

## Важно знать

- **Код будет публичным.** На бесплатном тарифе GitHub Pages работает только с публичными
  репозиториями. Секретов в коде нет, но тексты уроков увидит любой, кто найдёт репозиторий.
- **Это закрытый пилот.** Ссылку даём только знакомым семьям, нигде не публикуем.
  Поисковикам индексировать сайт запрещено (`robots: noindex`).
- **Без счётчиков, аналитики и форм.** GitHub как хостинг может записывать IP-адреса посетителей
  в свои журналы — это вопрос для юриста перед публичным запуском (docs/RISKS.md).
- **Доступность из России** без VPN нужно проверить на нескольких устройствах и у разных
  провайдеров — это часть пилота.

## Что теряется без HTTP-заголовков

GitHub Pages не даёт задать свои заголовки. Главная политика (`frame-src 'none'` и др.)
продублирована в `<meta>` и проверена в браузере: переход предпросмотра на чужой сайт
блокируется так же. Не работают только:
- `frame-ancestors 'none'` — сайт студии можно встроить во фрейм на чужом сайте;
- `Permissions-Policy` — для предпросмотра не критично: он и так в песочнице без доступа к камере и т. п.;
- `X-Content-Type-Options` — зависит от настроек GitHub Pages.

Для публичного запуска нужен хостинг, где заголовки задаёт сервер (см. docs/adr/0001).

## Пошагово (Windows)

1. **Аккаунт GitHub.** Зарегистрируйтесь на github.com.
2. **Git.** Установите Git for Windows с git-scm.com. Проверка в PowerShell: `git --version`.
3. **Репозиторий.** На GitHub: «New repository» → имя `codequest` → **Public** →
   ничего не добавлять (без README, .gitignore, лицензии) → «Create repository».
4. **Отправка кода.** В PowerShell в папке проекта (где лежит `package.json`):
   ```powershell
   git remote add origin https://github.com/ВАШ_ЛОГИН/codequest.git
   git push -u origin main
   ```
   Откроется окно входа в GitHub в браузере — войдите.
5. **Включите Pages.** В репозитории: Settings → Pages → Build and deployment →
   Source: **GitHub Actions**.
6. **Запустите выкладку.** Вкладка Actions → «Выкладка на GitHub Pages» → Run workflow
   (первая автоматическая попытка могла упасть, пока Pages не был включён — это нормально).
   Через 3–5 минут появится зелёная галочка.
7. **Ссылка:** `https://ВАШ_ЛОГИН.github.io/codequest/`

## Как обновлять сайт

После изменений в коде:
```powershell
git add -A
git commit -m "Что изменено"
git push
```
Через несколько минут сайт обновится сам. Перед первым своим коммитом представьтесь Git:
`git config --global user.name "Имя"` и `git config --global user.email "почта"`.

## Если выкладка упала

Actions → упавший запуск → шаг с красным крестиком → скопируйте последние строки лога.

## Проверить сборку для Pages локально

```bash
STATIC_EXPORT=1 BASE_PATH=/codequest npx next build   # результат — папка out/
```
В PowerShell: `$env:STATIC_EXPORT="1"; $env:BASE_PATH="/codequest"; npx next build`.
